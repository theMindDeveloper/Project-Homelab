# Monitoring, security logs and alerting, in one evening

**Date** 8 October 2026
**Author** TheMindDev
**Scope** From "Prometheus watches one node and nothing alerts" to: every machine
monitored, the router and the game servers monitored, firewall and website logs
with locations, CrowdSec watching, four generated dashboards, and 19 alert rules
sending to Telegram
**Outcome** All of it live the same evening. Built by the AI agent from the
[previous report](2026-10-08-ai-agent-least-privilege.md), every change as a
pull request that I read and merged, applied only after the merge.

> **Redaction.** No public address, no game ports, no tokens, no chat IDs, no
> router firmware version. Same rule as always,
> [`docs/99-security-notes.md`](../99-security-notes.md).

---

## 1 · Where it started

In the morning the state was:

- Prometheus scraped **one** of three nodes. pve-exporter was in the README and not
  in the lab.
- Grafana had community dashboard 1860, and nothing else.
- **Nothing alerted.** The README called it "the largest gap in the system".
- No logs anywhere. Who knocked on the game ports was unknown.

I asked for four things over the evening, one after the other:

1. Connect all three nodes to Prometheus and Grafana.
2. Better dashboards, a security dashboard, "where do connections come from".
3. The Pi, the NAS, the router and the game servers too.
4. Alerts for everything important, but efficient: no paid service, and not
   through the AI agent (that would cost tokens per alert).

## 4 · What broke, and what it taught

The useful part. Each of these cost between five minutes and an hour.

### Monitoring

1. **Every Proxmox gauge three times.** pve-exporter was asked for the *whole
   cluster* once per node. Fix: cluster data from one node, per-node extras from
   each ([prometheus.yml](../../compose/monitoring/prometheus/prometheus.yml)).
2. **The NAS rejected the compose file**, with nothing more than "Invalid
   configuration file". Two causes, found one at a time: a `$` in a regex
   (compose reads `$` as a variable), and UGOS refusing to mount the host's root
   folder at all. The container was made in the UGOS image screens instead, with
   one empty read-only folder per disk volume so disk usage still shows.
3. **"Space allocation 916 GiB" looked like a full NAS.** It was a community
   dashboard panel showing *size*, not *use* (34 % used), three times, once per
   node mounting the same share. One more reason for own dashboards.

### Logs and the map

4. **The map said "API KEY REQUIRED".** Grafana's default map tiles (CARTO) now
   need a key. ESRI's dark tiles don't.
5. **Game traffic showed 0.** It *was* logged, but on the DMZ side of OPNsense
   (interface `vtnet1`, direction out), not on WAN where the panels looked.
6. **"Blocked" was full of my own house.** OPNsense's WAN side is in the home
   network and sees every broadcast. All security panels now drop private source
   addresses.
7. **"Top countries" was one bar reading "65".** Loki hands Grafana one table, not
   one series per country; bar charts need "show every row".
8. **The NPM logs could not give a world map.** 272,000 requests, zero from the
   internet: NPM is LAN-only by design. The map is built from the firewall and
   the tunnelled website instead.

### Alerts

9. **The router exporter listened on 127.0.0.1** (version 3.x default), so
   Prometheus got "connection refused". Combined with an "internet down" rule
   that read "no data" as "down" (`or vector(0)`), that was **minutes away from a
   false 🔴 at night**. Both fixed.
10. **A rule that could never fire.** "Log collection stopped" compared with
    `< 1` instead of `< bool 1`, which returns 0 exactly when it should return 1.
11. **A false alarm on day one.** "Disk full within 7 days" fired immediately: its
    6-hour window held old series from before the `node` label existed.
12. **`$$A` vs `$A`.** Grafana expands `${VAR}` in contact-point files but not
    in alert-rule files. The habit from compose files (`$$`) broke a rule; only
    loading the files into a throwaway Grafana showed it.
13. **pve2 and pve3 are switched off to save power.** Naive rules would have sent
    a message every evening. Now: no "down" alert for those two, their guests only
    alert while the node is on, and "the firewall stopped logging" only counts
    while pve2 (where the firewall runs) is up.

### Process

14. **The agent raced its own merge-watcher twice.** Both applied the same merged
    PR within a minute; the second "backup" saved the already-changed file. Fixed
    by restoring the right backup from Git, and a rule: apply by hand only if the
    watcher clearly hasn't.
15. **The secret scanner was ignored once.** `check-secrets.sh | tail -1 && git
    commit` uses `tail`'s exit code, not the scanner's. Two findings (both false
    positives: variable *names* in the game exporter) were committed. Now the exit
    code is checked on its own line, and the two exact strings are in the
    allowlist with a comment.
16. **A Pterodactyl API key made through the API comes in two parts.** The usable
    key is identifier + secret. And the panel answered 403 to Python's default
    user agent.

## 5 · Decisions, and why

| Decision | Instead of | Because |
|---|---|---|
| Grafana alerting | Prometheus + Alertmanager | several rules need Loki; no extra container |
| my own Telegram bot | alerts through the AI agent, or a paid service | no tokens per alert, nothing in between on the path that must work when everything else is broken |
| CrowdSec **watch only** | a bouncer that blocks | a wrong ban locks out a player or me; first see how often it would be wrong |
| **no country blocking** | GeoIP block rules | noise reduction, not protection; would need new accounts; can break Steam server lists. Revisit with data |
| our own game-exporter | a 0-50 star exporter from GitHub | 158 readable lines vs. trusting unknown code with panel credentials |
| dashboards generated by Python | clicking in Grafana | a change is a diff; one look everywhere; rebuild = one command |
| DB-IP Lite for locations | MaxMind GeoLite2 | no account needed |
| pve2/pve3 off = normal | alert on every host | saving power is a feature, not an incident |

## 6 · How it was checked

- Every dashboard query run against the live Prometheus and Loki before each PR:
  the last full run was **915 queries, 0 errors** (the Hosts dashboard once per
  host). The script that does it is now
  [`scripts/grafana/check_dashboards.py`](../../scripts/grafana/check_dashboards.py).
- Every alert rule's query run against live data: none returning "problem" at
  deploy time (the two that did were fixed: point 11, and one guest that is
  stopped on purpose and is now excluded with a comment).
- The game rule's logic unit-tested with `promtool test rules`.
- All alerting files loaded into a throwaway Grafana of the same version before
  going live; message template rendered with fake alerts.
- A real Telegram test message; FRITZ!Box values cross-checked against the
  router's own UI; the Pterodactyl key confirmed to work from the monitoring
  host and to be refused from anywhere else.

## 7 · What is still weak

- **Logins on the nodes, the Pi and the NAS are not collected.** Only LXC 102's
  SSH log is. A Proxmox web-UI brute force would go unseen.
- **The game alert cannot tell "I stopped it" from "it crashed".** The panels'
  activity logs would, but the monitoring user may not read them yet.
- **Prometheus keeps 15 days.** The examples say 90; the lab has not switched.
- **The location database is refreshed by hand**, monthly.
- **No per-container metrics** (cAdvisor not deployed).
- **"Internet down" arrives after the internet is back.** Telegram is on the other
  side of the broken line. Still useful as a record.
- **Two findings from this work are open decisions,** not fixes: a guest set to
  start at boot that is stopped on purpose (excluded from the alert, with a
  comment), and Docker apparently installed directly on one Proxmox host.

---

## 8 · What I learned

- **Alerting is easy to switch on and hard to make honest.** Most of the work was
  making rules *not* fire: dead exporters, switched-off nodes, old series.
- **Test against the real thing before deploying.** Almost every problem in
  section 4 was found by running queries against live data or by loading files
  into a throwaway Grafana, not by reading the config.
- **Logs and metrics answer different questions.** "How many" is Prometheus,
  "who exactly" is Loki. Putting visitor IPs into Prometheus labels would have
  killed it.
- **Read-only everywhere is possible.** Every exporter, every token and every
  user created for this can only read. Nothing in the monitoring can change the
  lab it watches.
